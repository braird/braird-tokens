# CLAUDE.md — braird-tokens

Agent context for **braird-tokens** — Braird's platform-neutral design-token source. Read
this and [`GATING.md`](GATING.md) before changing anything.

## What this repo is

One DTCG/JSON source (`tokens/**`) generated by **Style Dictionary (v4)** into three
committed bindings (`build/`): CSS custom properties (surfc, surfc-web), a Compose Kotlin
`object` (braird-android), and Swift constants (braird-ios). Colour / type / space / radii /
font-intent are defined **once**; every client reads generated output. This is the single
token vocabulary the whole ecosystem shares — components are NOT shared (each platform
reimplements them against these tokens).

The token *values* were lifted from `surfc/src/design/tokens.css` (SUR-679 Braird ·
Resurface palette) with **names unchanged**, so aliased surfc components recolour with no
edits. **Type is the Braird two-face system (v0.2.0):** `--font-base` = Hanken Grotesk (all
UI/body), everything serif (`--font-serif` / `--font-display` / `--font-stat` /
`--font-front-door`) = Lora. The Sometype Mono front-door face (SUR-508) is retired — the
`--font-front-door` token stays (now Lora) for consumer compatibility. Font *intent* only
lives here; consumers bundle the Hanken Grotesk + Lora binaries.

## Commands

```bash
npm install
npm run build   # regenerate build/ from tokens/**
npm run check   # build + scripts/selfcheck.mjs (assert-based)
npm run drift   # build + `git diff --exit-code build/` (CI-enforced)
```

Node `>=22`. Runs on Windows/Linux/macOS — pure Node; no native toolchain needed to
generate (compiling the emitted Swift needs macOS, but that is the consumer's concern).

## Layout

- `tokens/primitive/` — raw brand hues, **reference-only** (not emitted).
- `tokens/light/`, `tokens/dark/` — mode-varying colour: surfaces/text/border **plus**
  accent/custom/idea-inks (the Braird Screens design lifts these for dark). `dark/` is the
  real "Braird at night" theme imported from the Claude Design project.
- `tokens/brand/` — mode-invariant colour only (semantic status + scope; not dark-tuned).
- `tokens/type/`, `space.json`, `radius.json`, `shadow.json` — mode-less scale + geometry.
- `platforms/css/web-only.css` — safe-area/z-index/breakpoints/transitions/nav: CSS-emitter
  layer, deliberately NOT in the neutral source (native has its own equivalents).
- `scripts/build.mjs` — SD config + the three custom emitters. `scripts/selfcheck.mjs` — the
  post-build assertions.
- `build/` — generated + committed + drift-guarded.

## Rules — always follow these

- **`build/` is generated, never hand-edited.** Change `tokens/**`, run `npm run check`,
  commit the regenerated `build/`. The `drift` CI regenerates through the same script and
  fails on any divergence — hand edits are erased on the next build anyway.
- **Names are a contract.** A token rename fans out to four consumers (surfc, surfc-web,
  braird-android, braird-ios). Keep names matching `surfc/src/design/tokens.css` unless a
  ticket explicitly renames; new public names get naming review (see GATING).
- **Web-only tokens stay in `platforms/css/web-only.css`,** not `tokens/**`.
- **Fonts:** the source carries family/weight *intent* only. Binaries stay with each
  consumer (woff2 in web repos, ttf/otf in native).
- Conventional Commits; reference `SUR-XXX`. Every PR to `main` adds a `CHANGELOG.md`
  `[Unreleased]` entry (CI-enforced).

## Workflow

- **No stacked PRs.** Branch every change off `origin/main`
  (`git checkout -b feature/short-desc origin/main`); every PR's base is `main`. If a branch
  needs `main` merged in, **STOP and flag the founder** — do not rebase/merge `main` yourself.
- You are an **agent under the gate**, not autonomous. Write your plan, name the gate,
  propose changes. **Do not merge** — the founder reviews and merges.
