# Changelog

All notable changes to braird-tokens are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); every PR to `main` must add an
entry under `[Unreleased]` (CI-enforced, dependabot-exempt).

## [Unreleased]

### Changed

- **README: no old product name.** The consumer example and the `DESIGN.md` note name no repo
  by its old name. Docs only; no token change.
- **Canonicalise on the Braird two-face type system (SUR-642).** The brand is now exactly
  **Hanken Grotesk** (all UI/body) + **Lora** (all serif/editorial), matching the Braird app
  design (`braird/screens/app.css`). Token changes: `--font-base` `IBM Plex Sans → Hanken
  Grotesk`; `--font-serif` `EB Garamond → Lora`; `--font-front-door` `Sometype Mono → Lora`.
  `--font-display` / `--font-stat` stay Lora. **The Sometype Mono front-door face (SUR-508)
  is retired** — the `--font-front-door` token is kept (now Lora) so consumers referencing it
  don't break, but its distinct mono identity is gone. Spine change (front-door contract) —
  **founder sign-off**. Consumers must bundle Hanken Grotesk + Lora and drop IBM Plex Sans /
  EB Garamond / Sometype Mono when they re-pin. Shadows were already forest-tinted (canonical),
  so only the font intent changes.

## [0.1.0] - 2026-07-04

### Added

- **Stand up `braird-tokens` — the platform-neutral design-token source (SUR-642).** One
  DTCG/JSON source under `tokens/**` is generated by Style Dictionary (v4) into three
  bindings committed under `build/`:
  - **CSS custom properties** (`build/css/tokens.css`) for `surfc` + `surfc-web`.
  - **Compose Kotlin** (`build/compose/BrairdTokens.kt`, `object BrairdTokens`) for
    `braird-android` — wired by SUR-763.
  - **Swift** (`build/swift/BrairdTokens.swift`, `enum BrairdTokens`) for `braird-ios` —
    wired when iOS UI work begins.
  - Token **values lifted verbatim** from `surfc/src/design/tokens.css` (SUR-679 Braird ·
    Resurface palette); every token **name is unchanged** so aliased components recolour
    with no code edits. `--font-front-door` (Sometype Mono, SUR-508) preserved.
  - **Web-only tokens** (safe-area `env()`, z-index, breakpoints, transitions, nav widths)
    stay in the CSS emitter (`platforms/css/web-only.css`), not the neutral source.
  - **Drift check** (`.github/workflows/drift.yml`): CI regenerates and fails if `build/`
    diverges from `tokens/**`. Changelog gate cloned from braird-core.
- **Dark mode — "Braird at night", system + manual (SUR-642).** The CSS emit ships `:root`
  (light), `[data-theme="dark"]` (manual override, always wins), and a
  `@media (prefers-color-scheme: dark)` block that yields to an explicit `data-theme="light"`.
  Compose/Swift emit parallel `ColorLight` / `ColorDark` objects. **Values are the real
  Braird Screens dark theme** (imported from the Claude Design project,
  `braird/screens/app.css`): deep-forest ground `#0C1A14`, warm paper-white ink `#F1F5EB`,
  greens + idea-inks **lifted** for the dark ground (accent `#2F9E63`→`#4FB87A`). Because the
  design lifts accent / custom / idea-inks, those moved out of the mode-invariant `brand/`
  layer into `tokens/light` + `tokens/dark`. (Two idea-inks the 6-branch design screen omits —
  `relationships-ethics`, `world-meaning` — carry a derived lift, flagged in `tokens/dark/color.json`.)
- **`--font-stat` — dedicated stat-box face (SUR-642).** Set to the Braird Screens stat
  treatment: **Lora** (display serif), 28px / weight 600 / line-height 1 — not the base
  `.stat-value` EB Garamond. Emitted to CSS + Compose + Swift so stat typography is one
  cross-platform token instead of a `styles.css` one-off.
